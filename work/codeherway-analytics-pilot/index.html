An analytics pilot that earned its off switch

I wanted to know where learners get stuck in HTML, but a dashboard that looks right can still count the wrong people. We kept the pilot off while testing whether the report counted the intended cohort and applied its privacy rules.

  • Owner-only reporting requirement
  • Four eligible starters stay suppressed
  • Hosted and scheduled checks remain open

Evidence Snapshot

Implementation

The private analytics safeguards pull request covers access restrictions and QA activity handling. A separate private retention pull request records the scheduled cleanup implementation. This page summarizes those records without exposing private receipts.

Boundary fixture

Four eligible starters plus one excluded QA account must remain below the display threshold; five eligible starters may display a count. Testing far below the threshold would not catch the exclusion error.

Evidence boundary

A merged migration or a schedule is not proof that deletion actually ran. These are local fixture and implementation results, not live learner counts.

Problem and Users

As pilot owner, I needed numbers I could explain without including QA activity or exposing results to unauthorized viewers. In a small cohort, one incorrectly counted account can change whether a result is displayed.

Key Product Decisions

Limit the report to the owner. Exclude QA activity instead of using it to reach the display threshold. Keep the threshold in place even when it means a demo cannot show a count. Leave collection and reporting off until the pilot checks pass.

Engineering Decisions

Exercise the exact threshold boundary with controlled accounts. Verify retention at three distinct levels: the migration exists, the job is scheduled, and a synthetic record actually expires. Each level needs its own evidence.

Accessibility Considerations

The documented work focused on report access and counting. No accessibility evaluation of the hosted report was recorded at this checkpoint.

Performance Considerations

The local fixtures did not measure hosted report latency or dashboard performance. Those remain separate checks before treating the pilot as ready.

Current Status and Limits

The work established implementation and local fixture evidence. Scheduled expiry, hosted owner-only access, and Preview reconciliation remained open verification items. No live pilot or privacy outcome is claimed.

What I Would Improve Next

Verify owner-only access and suppression in an isolated Preview with synthetic accounts. Reconcile exact totals against controlled fixtures and record a real scheduled cleanup before treating retention as verified.
