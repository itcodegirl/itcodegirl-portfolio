When a quiz should show code as code

While taking the first HTML quiz, I had to pick the tags out of a sentence before I could think about what the question wanted me to demonstrate. An <h1> item made the problem obvious: a heading’s meaning and its default browser styling are different ideas. The question needed to say which one it was testing.

Evidence Snapshot

What changed

The platform change added a read-only, editor-style code panel above the prompt. A separate curriculum change revised the first HTML quiz content. Both source pull requests are private; this page gives their public-safe summary.

What was checked

The review recorded 78 focused local tests and applicable GitHub checks. A revised question was exercised locally at phone and desktop widths for code/question order, keyboard navigation, and answer selection.

Evidence boundary

The checks cover presentation and focused interaction. They do not measure comprehension, score changes, or screen-reader behavior.

Problem and Users

Beginners interpreting HTML should spend their effort reading markup and reasoning about its meaning. Buried code, or an answer that mixes heading semantics with default styling, adds difficulty unrelated to the skill being assessed.

Key Product Decisions

Put the read-only code sample above the question, preserve real line breaks, and make the prompt explicit about what the learner is judging. Text-only questions keep their existing layout. Learners do not have to run or edit code to answer.

Engineering Decisions

The code panel appears on three questions in the first quiz. Answer selection and scoring stay separate from presentation. Local checks confirmed the code precedes the prompt and the existing keyboard interaction still works.

Accessibility Considerations

The local keyboard check covered tab order to an answer and answer selection. It was not a screen-reader evaluation; that remains a separate review.

Performance Considerations

The display reuses the platform’s existing syntax highlighter and adds no editable editor or new public-entry preload. No load-time measurement is claimed.

Current Status and Limits

The documented checkpoint supports the layout change and focused local interaction checks. It does not show that beginners understand the question better, guess less, or earn different scores. The combined learner experience still needs hosted review.

What I Would Improve Next

Watch a few beginners answer in Preview and ask what they looked at. Check whether their explanations focus on heading meaning or browser styling. Capture a dated before-and-after image only after a public-safe learner view is available.
